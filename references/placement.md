# 章节归属与插入位置判断细则

## 场景 1：知识点 D 属于已有章节 A/B/C 之一

判断依据：D 的"关键问题"（线索栏）是否被某章节的线索范围覆盖。

例：已有章节 A《相机标定》、B《ISP 流水线》、C《ROS2 话题》。新学"内参矩阵的畸变系数" →
属于 A → 写进 A 主题文件，新增一个知识点块（三栏格式），**不开新文件**。

## 场景 2：先学架构、后学细节（逐步完善）

架构性章节先建立（如《hobot_mipi_cam 总体架构》），后续学到的细节（某线程的行为、某参数的
含义）全部**补进对应章节的知识点块**，或在章节内新增块。判断口诀：**细节永远不新开顶层章节**，
只有"新的独立主题"才开新文件。

## 场景 3：D 不属于任何已有章节 → 新开主题文件 + 选插入位置

插入位置按**知识脉络的前后关系**决定，不是默认文末：

1. 看 index.md 现有章节顺序，找 D 的"上游"（D 依赖/建立在它之上）和"下游"（依赖 D 的）。
2. 插到"最后一个上游之后、第一个下游之前"。
3. 上下游都不明确 → 插到主题最接近的章节旁边（同类聚拢）。
4. 实在孤立 → 才放文末，并在汇报里说明。

例：index 顺序为 A《标定》→ B《ISP》→ C《话题通信》，新学《YUV 色彩格式》——它是 B 的上游
（ISP 输出 NV12）→ 插在 A 与 B 之间。

## 场景 4：新内容修正了笔记已有表述

例：笔记里写"7mm 夹槽是装配公差"，后续对话确认"7mm 是设计尺寸，公差另算" →
**直接改写**那处主栏/总结栏，不追加"更正：…"。修正后的表述即为最终版本。

## 场景 5：不记录的内容

- 闲聊、寒暄、与学科无关的操作问题（如"帮我看看某个命令"）
- 笔记中已完整覆盖的知识点（除非有修正）
- 纯过程性信息（安装步骤、报错排查过程）——除非用户明确说"这个要记"

## 合并去重（拆解导入时）

两个知识点"重复"的判据：线索栏的关键问题实质相同。合并时：
- 主栏取两者并集，删冗余表述
- 易错点取并集
- 总结栏保留更准确的一版（通常取用户措辞版）
- index.md 只保留一个条目
